Capabilities

为真实工作流而设计

不是又一个「开发者仪表盘」，而是你桌面的空间整理器。内容优先、项目中立、低视觉噪音。

一次扫描，自动建档

指向任意父目录，扫描器读取一级子目录并依据特征文件判定技术栈；已导入的项目会被标记并置灰，杜绝重复。node_modules、target、dist、venv 等 8 类噪声目录与全部隐藏目录自动跳过。

scan_directory · import_projects · 只读，不改磁盘

Ctrl+K 秒级抵达

名称、简介、路径、GitHub 地址、标签、技术栈全字段检索，键盘直达，不离开键盘流。

全字段匹配 · 最近记录 · Enter 打开

标签 × 集合

标签描述项目「是什么」，集合表达你「怎么归类」。两个正交维度，任意组合筛选。

事务内全量绑定 · 级联清理

Git 只读解析

分支、最后提交、dirty 状态、remote origin 全部读取。Git 不可用或没装 CLI 时静默降级，绝不影响项目加载。

.git/config INI 解析 · 无 CLI 依赖

五种状态追踪

进行中 / 计划中 / 暂停 / 已完成 / 已归档。状态变更自动写入活动流，项目详情页可回看完整时间线。

activity 表 · 最近 50 条 · 索引加速

全局待办池，可挂到具体项目、设置截止日期，也可完全独立存在。做完一件事，勾掉它——不需要为此再装一个 App。

list / create / update / toggle / delete

八类链接 + 一键直达

GitHub / 官网 / 文档 / 设计稿 / Demo / 论文 / 云盘 / 其他，为项目挂上它所有的入口。同时在系统里打开文件夹、拉起终端、复制路径——Windows、macOS、Linux 三套分支各自走原生命令。

Git · Read Only

拿得到信息，绝不碰你的仓库

只读、可降级、无副作用。Git 信息是锦上添花，永远不该成为加载失败的原因。

// remote origin 直接解析 .git/config —— 不依赖 git CLI
fn read_remote_url(repo: &Path) -> Option<String> {
    let cfg = repo.join(".git/config");
    let text = fs::read_to_string(cfg).ok()?;
    // 定位 [remote "origin"] 段，取 url = ...
    parse_ini_section(&text, "remote", "origin")
        .map(normalize_remote_url)
}
